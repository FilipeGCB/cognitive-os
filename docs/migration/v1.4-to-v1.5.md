# Migration: Cognitive OS V1.4 → V1.5

V1.5 is an additive development line. Existing V1.4 skill behavior, decision
pack format, adapter registry and Hermes harness remain canonical; the new
contracts extend them.

## Runtime and records

- `skills/cognitive-os/VERSION` and public development metadata are now
  `1.5.0-dev`.
- Run and capability records gain executable state validation. Availability,
  authentication, run consent, invocation and result are independent.
- Full Flow/Audit records the expanded ledgers, research budget, provider/host
  failures, stop and next proof. Private chain-of-thought is still excluded.
- New usage traces default to `OFF`; local diagnostics and shared diagnostics
  are distinct modes.

## Capability behavior

Existing capabilities are checked first, then local discovery, then an approved
external discovery asset when one is actually available. Find Skills/Find MCP
are search mechanisms, not trusted candidates. Each candidate needs its own
provenance, permission review and Gauntlet. Temporary execution follows the
same security and consent boundaries as installation.

NotebookLM/Grounded Corpus remains optional and host-dependent. Cross-source,
revisitable or internal-plus-external research now triggers a strategy
reconsideration, with an explicit fallback when the corpus is unavailable.

## Distribution and evidence

Each distribution target declares included, projected and omitted assets plus
feature availability and schema enforcement. Validation must run against the
actual copied/installed artifact. Release evidence must bind to the exact
candidate SHA and cannot reuse behavioral evidence from another commit.

## Telemetry and diagnostics

No action is required from existing users. The public client does not upload by
default. Sharing requires a preview, explicit versioned consent, a host send
capability, Gate T evidence and a configured private collector. Forensic
diagnostics are a separate bounded opt-in flow and exclude raw conversation.
