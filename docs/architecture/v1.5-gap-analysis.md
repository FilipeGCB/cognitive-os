# Cognitive OS V1.5 Architecture Gap Analysis

Source: `docs/specs/2026-09-04-cognitive-os-v1.5-public-final.md`
Baseline: `origin/main` at `41a14aa839c87609597cb0cdd3ff81cd06b61135`

The analysis was completed before introducing new structural surfaces. Existing canonical components are extended wherever they can represent the V1.5 contract.

| Current component | V1.5 requirement | Decision | Justification |
|---|---|---|---|
| `skills/cognitive-os/SKILL.md` | compact discovery, research budget, grounded strategy, self-improvement, side-effects and telemetry rules | EXTEND | It is the sole runtime cognitive source and already carries the V1.4 behavior. |
| `skills/cognitive-os/references/capabilities.md` and `references/workflows.md` | local/external discovery and routed workflows | EXTEND | Existing references already define abstract capabilities and `/capability`; new rules fit the same surface. |
| `skills/cognitive-os/references/research-routing.md` | Web→Corpus migration and budget checkpoints | EXTEND | Existing research router is canonical and vendor-neutral. |
| `skills/cognitive-os/references/source-authority.md` | truth-domain mapping and reconciliation | EXTEND | Existing source-authority contract already governs current-vs-historical conflicts. |
| `adapters/registry.json` + `adapters/schema.json` | discovery assets, candidate provenance, host support and status | EXTEND | The existing registry already models source/version/license/auth/permissions/Gauntlet. A second discovery registry would duplicate it. |
| `bootstrap/cognitive_os_bootstrap.py` | deterministic planning, state separation and safe consent decisions | EXTEND | Existing side-effect-free bootstrap is the correct host-neutral policy seam. |
| `evals/e2e/run_hermes_e2e.py` | account-bound isolation, run binding and observable mutations | EXTEND | It is the existing Hermes harness; replacing it would discard V1.4 runtime evidence semantics. |
| `skills/cognitive-os/schemas/*.md` | human-readable contracts plus executable validation | EXTEND | Markdown contracts remain useful; matching JSON schemas are added beside them. |
| `evals/` and `tests/` | V1.5 eval families and regression gates | EXTEND | Existing validators/runners are preserved and versioned rather than replaced. |
| `distribution/*/README.md` and host wrappers | installed-artifact feature declarations | EXTEND | Existing targets remain the distribution mechanism; manifests make their projected fidelity explicit. |
| `telemetry/` | Flight Recorder and opt-in sharing client | NEW | No existing telemetry runtime/client exists; the spec explicitly defines this as a separate, optional public surface. It is not a second cognitive core. |
| private telemetry collector | optional Gate TC backend | NEW, CONDITIONAL | No collector is present in the public tree. It may only be created in a separate private repository after Gate T and programmatic private-visibility proof. |
| `bootstrap/discovery-assets.yaml` | concrete Find Skills/Find MCP registry | NOT CREATED | Existing adapter registry is structurally sufficient. Exact discovery asset identities were not proven by repository/history/issue evidence; they remain `BLOCKED` instead of receiving an invented substitute. |

## Discovery asset evidence decision

Repository search, Git history and GitHub issues/PRs found references to the abstract concepts but no canonical owner/repository/version/mechanism for an originally selected Find Skills or Find MCP asset. No external project with a similar name was pinned. The V1.5 registry will represent external discovery as `BLOCKED`/`UNAVAILABLE` unless a future evidence record proves the exact asset identity; local discovery and all other work continue independently.
