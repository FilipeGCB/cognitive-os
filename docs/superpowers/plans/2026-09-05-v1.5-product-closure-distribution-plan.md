# Cognitive OS V1.5 Product Closure & Distribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close Cognitive OS V1.5 with mandatory Find Skills/Find MCP discovery, explicit-consent telemetry with a real collector and improvement queue, complete distribution packaging, and final release evidence.

**Architecture:** Keep deterministic planning separate from side effects. Add a narrow installer boundary for local hosts, bundle a read-only Official MCP Registry client, deploy the telemetry collector privately on Supabase, and keep self-improvement as an evidence queue that feeds reviewed specs/PRs rather than silent mutation. ChatGPT/Claude packaging reuses the same core skill and host-specific adapters.

**Tech Stack:** Python 3 standard library, JSON Schema/contracts, GitHub Actions, Supabase Postgres + Edge Functions (Deno/TypeScript), Agent Skills (`skills@1.5.23`), MCP Registry v0.1 API, ChatGPT Apps SDK/MCP submission contract, Claude plugin manifest.

**Spec:** `docs/superpowers/specs/2026-09-05-v1.5-product-closure-distribution-design.md`

## Global Constraints

- No local LLM in release/conformance gates.
- Find Skills and Find MCP discovery are mandatory post-install capabilities.
- Optional telemetry is OFF by default and requires explicit affirmative consent.
- No prompt/response/document/free-text/PII/secret/path/private URL/chain-of-thought telemetry.
- Candidate discovery never authorizes candidate execution or installation.
- Self-improvement can enqueue reviewed candidates; it cannot silently mutate the active methodology.
- Never claim a public plugin directory publication before external platform approval.
