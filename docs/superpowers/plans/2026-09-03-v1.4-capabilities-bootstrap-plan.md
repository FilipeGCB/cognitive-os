# Cognitive OS v1.4 Capabilities and Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build host-neutral capability routing, runtime truth records, consent-aware bootstrap logic, and isolated adapters for Deep Research, Grounded Corpus Research and selected external companions.

**Architecture:** `skills/cognitive-os/` defines abstract capability contracts and policies; executable bootstrap logic lives outside the runtime skill in `bootstrap/` and returns plans/actions rather than silently mutating systems. Adapters are isolated under `adapters/`, each pinned and independently testable. Native host capabilities always win when sufficient.

**Tech Stack:** Python 3.11+ standard library, JSON manifests, shell commands emitted only as explicit installation plans, GitHub-hosted adapter metadata.

**Spec:** `docs/superpowers/specs/2026-09-03-cognitive-os-v1.4-public-product-design.md`

## Global Constraints

- Discovering a capability never authorizes installation.
- One-time consent permits only light, local, reversible, user-space components with no secrets, sensitive persistent access or external write capability.
- Docker, large downloads, accounts, secrets, sensitive data, privileged changes and write-capable integrations always require specific confirmation.
- Existing sufficient native capabilities must prevent redundant installation.
- Vendor/tool names are implementations, never the cognitive architecture.
- Runtime truth is `availability + invocation + result`; availability alone is not execution.

    snap = CapabilitySnapshot("Grounded Corpus Research", "AVAILABLE", "host-native")
    decision = plan_gap_fill(snap, ConsentProfile(True), [])

def test_heavy_candidate_requires_specific_confirmation():
    snap = CapabilitySnapshot("Grounded Corpus Research", "UNAVAILABLE", None)
    candidates = [{"id": "local-rag", "heavy": True, "account": False, "write": False, "approved": True}]
    decision = plan_gap_fill(snap, ConsentProfile(True), candidates)
    assert decision.action == "ASK_SPECIFIC_CONSENT"

- [ ] **Step 2: Run and verify failure**

Run: `python -m unittest tests.test_bootstrap -v`

Expected: FAIL because module does not exist.

- [ ] **Step 3: Implement minimal dataclasses and planner**

Use only standard-library `dataclasses`, `json`, `os`, `pathlib`, `shutil`, `subprocess` for detection. `plan_gap_fill()` must return decisions without executing external commands.

Decision actions:
- `USE_EXISTING`
- `AUTO_INSTALL_ALLOWED`
- `ASK_SPECIFIC_CONSENT`
- `NO_APPROVED_IMPLEMENTATION`
- `BLOCKED`

A candidate is auto-installable only when all are true: approved, user-space, light, reversible, no account, no secret, no sensitive persistent access, no write, no privileged change.

- [ ] **Step 3: Implement routing**

Rules:
- simple/current claim → Web Search;
- multi-source current question → composed research;
- large/high-stakes external research where additional breadth/depth can change decision → native Deep Research when available;
- host requires user activation → explain why and exact activation step, then continue after activation;
- repeated closed-corpus reasoning → Grounded Corpus Research;
- multi-page structured extraction → Structured Crawl only when ordinary web search is insufficient.
