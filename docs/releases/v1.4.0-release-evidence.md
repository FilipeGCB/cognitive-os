## Packaging defects found by the gates

The release gates caught and caused correction of real issues before release, including:

1. a literal distribution-contract mismatch in the OpenAI documentation test;
2. invalid YAML frontmatter in `skills/cognitive-os/SKILL.md` that made the Agent Skills CLI reject the skill;
3. incomplete behavioral-eval fixtures that referred to context not actually supplied to the SUT;
4. an Audit-mode conformance harness defect that used an insufficient fixed generation budget and allowed a grader to confuse observable audit ledgers with private chain-of-thought.

For item 4, regression tests were added first and observed failing on commit `4a77049e4dfc149b1d4f89f3588429e6e192e9b7`. The harness fix on `9ffe814c13820d37abae0e6d9d4e4e19dc447419` then passed those tests in CI and passed the targeted critical `V14-C12` case with both the SUT's separate grader invocation and an independent model-family cross-grader.

These findings are evidence that package, behavioral and harness-quality checks are materially different from source inspection alone.

## Capability / companion status

No third-party companion is promoted as `supported` or installed by default in v1.4.0.

- `notebooklm-py` / NotebookLM MCP: candidate, Gauntlet status `test`; pinned at v0.8.2; specific consent and account authentication required. CI proves package/entrypoint installability but not authenticated service behavior.
- OpenNotebookLM: preferred open-source candidate for the next direct grounded-corpus integration test; not default/supported.
- Open Notebook: candidate; not default/supported.
- SurfSense: `continue-research`; broader research platform and mixed licensing in part of the repository; not default/supported.
- AnythingLLM: candidate; not default/supported.
- Firecrawl: candidate for Structured Crawl; no bundled/default install.

Therefore the release does not claim runtime validation of a companion until the corresponding live E2E evidence exists.
