## Packaging and harness defects found by the gates

The release gates caught and caused correction of real issues before release, including:

1. a literal distribution-contract mismatch in the OpenAI documentation test;
2. invalid YAML frontmatter in `skills/cognitive-os/SKILL.md` that made the Agent Skills CLI reject the skill;
3. incomplete behavioral-eval fixtures that referred to context not actually supplied to the SUT;
4. an Audit-mode conformance harness defect that used an insufficient fixed generation budget and allowed a grader to confuse observable audit ledgers with private chain-of-thought;
5. Hermes `mcp test` zero-exit negative outcomes, requiring semantic output classification instead of trusting shell exit code;
6. NotebookLM E2E initially attempting interactive MCP configuration, corrected to fail closed and require preconfiguration;
7. a dynamic Hermes MCP tool-search path that was brittle for the local Gemma SUT, corrected in the isolated E2E profile by using eager MCP tools;
8. an invalid NotebookLM toolset name (`mcp-notebooklm`) and then an overly narrow `skills` allowlist that excluded the actual `notebooklm` MCP server; final E2E uses the real configured server name: `skills,notebooklm`.

For item 4, regression tests were added first and observed failing on commit `4a77049e4dfc149b1d4f89f3588429e6e192e9b7`. The harness fix on `9ffe814c13820d37abae0e6d9d4e4e19dc447419` then passed those tests in CI and passed the targeted critical `V14-C12` case with both the SUT's separate grader invocation and an independent model-family cross-grader.

For the later Hermes/NotebookLM issues, the fixes were also exercised through targeted RED/GREEN regression cycles before the final same-candidate E2E run.

These findings are evidence that package, behavioral, host-integration and harness-quality checks are materially different from source inspection alone.

### E2E truth discipline

The E2E harness records availability, invocation and result separately. It does not use assistant prose alone as evidence of tool execution. Only `AVAILABLE + CALLED + SUCCESS` supports an unqualified execution claim. H14-E06 intentionally proves that a missing capability remains visible as `UNAVAILABLE + NOT_CALLED + UNAVAILABLE` rather than being fabricated as executed.
