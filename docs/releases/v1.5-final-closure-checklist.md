## Corrected OpenAI/API boundary

Creating, testing, submitting or installing the ChatGPT/Codex plugin does **not** inherently require buying an OpenAI inference API key.

The repository contains an optional remote API conformance workflow for maintainers who deliberately want additional automated model QA. That workflow:

- has no provider/model default;
- requires explicit remote configuration when intentionally used;
- never falls back to a local model;
- is optional QA evidence, not a Plugin Directory requirement and not a V1.5 release blocker.

See [`docs/releases/v1.5-remote-conformance-runbook.md`](v1.5-remote-conformance-runbook.md).

## Remaining required work before stable `v1.5.0`

### 1. Freeze product scope and claims

Implementation scope is closed. Subsequent commits may only fix failed gates, correct evidence/claims, perform real host-validation wiring, or promote stable metadata.

### 2. Resolve ChatGPT host claim

The release has two truthful choices:

**A. `HOST_E2E_VALIDATED`** — only after a real ChatGPT host smoke using the deployed MCP/plugin surface, including `find_mcp`, `telemetry_status`, consent rendering, decline-without-send and one explicitly approved diagnostic send.

**B. `PLUGIN_SUBMISSION_READY / HOST_SMOKE_PENDING`** — allowed when the package/MCP/submission artifacts are complete but the actual ChatGPT host surface is not available for private smoke before core release.

A fabricated `PASS` is never allowed. No paid API key is required merely to choose either truthful plugin claim.

### 3. Host validation without Hermes lock-in

Hermes is **not part of Cognitive OS** and is not a dependency users must install. It is an optional compatibility host.

A live Hermes E2E may be recorded as additional compatibility evidence when available, but Hermes unavailability does not block the core release unless release notes explicitly promise a Hermes-verified claim.

### 4. External plugin-directory state

Repository readiness and public directory publication are different states.

- OpenAI/Claude package may be `SUBMISSION_READY` before external review.
- `SUBMITTED` only after a real platform submission.
- `APPROVED/PUBLISHED` only after the platform reports that state.
- Waiting for third-party review does not keep the Cognitive OS core permanently in `1.5.0-dev` if the core release claims are otherwise truthful.

### 5. Promote release metadata to stable `1.5.0`

After the final product/host claims are fixed:

- synchronize `skills/cognitive-os/VERSION`, `.codex-plugin/plugin.json`, Claude marketplace metadata and distribution manifests;
- update changelog/release notes;
- refresh release evidence for the final candidate/claims;
- re-run secret/PII/privacy/distribution/reference validation.

### 6. Final release path

- final deterministic/package/privacy/CI run green;
- release-evidence/claims review;
- remove Draft status from PR #5;
- merge PR #5 to `main`;
- run post-merge validation;
- create `v1.5.0` only from the verified `main` SHA.

## Explicitly outside V1.5 after this closure

- new capability adapters/providers beyond those already committed;
- additional discovery registries beyond Find Skills + Official MCP Registry;
- richer telemetry dashboards/BI/analytics products;
- automatic code/spec mutation from telemetry without normal review/promotion;
- new methodology lenses/workflows unrelated to a release blocker;
- generalized hosted agent runtime/SaaS architecture;
- making Supabase part of the Cognitive OS reasoning core;
- making paid inference API usage a mandatory plugin-install/release dependency.

## Definition of done

V1.5 is complete when all release claims are narrowed to evidence actually observed, stable `1.5.0` metadata/evidence is synchronized, final CI is green, PR #5 is merged, and `v1.5.0` is published.

ChatGPT host smoke, Hermes compatibility and public marketplace review are tracked independently according to the claims actually made. Optional paid API conformance may add evidence but does not block release.
