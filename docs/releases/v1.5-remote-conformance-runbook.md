# Cognitive OS V1.5 — Final Remote Conformance Runbook

**Status:** release blocker runbook  
**Workflow:** `.github/workflows/conformance.yml` / `v1.5-conformance`  
**Required profile:** `final` (58 cases)  
**Local LLMs:** prohibited

## Approved default pair

The workflow is prefilled with an independent cloud pair:

### SUT

```text
provider: openai
base_url: https://api.openai.com/v1/chat/completions
model: gpt-5.6-terra
secret: COGNITIVE_OS_CONFORMANCE_API_KEY
```

GPT-5.6 Terra is the current balanced GPT-5.6 tier for professional work and supports Chat Completions.

### Independent grader

```text
provider: google-gemini
grader_base_url: https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
grader_model: gemini-3.7-flash
secret: COGNITIVE_OS_GRADER_API_KEY
```

Gemini 3.7 Flash is a separate-provider GA model and is exposed through Google's OpenAI-compatible Chat Completions surface.

The pair is intentionally provider-independent. Do not point both SUT and grader at the same provider/model family for stable release evidence.

## One-time setup

In GitHub repository settings, create two Actions repository secrets:

```text
COGNITIVE_OS_CONFORMANCE_API_KEY = <OpenAI Platform API key>
COGNITIVE_OS_GRADER_API_KEY      = <Google Gemini API key>
```

Do not paste either secret into workflow inputs, commits, PR comments, logs, issues or documentation.

ChatGPT/Claude/Gemini consumer subscriptions are not treated as API credentials. The corresponding API projects must have enough billing/quota for the 58-case run.

## Run

GitHub repository -> Actions -> `v1.5-conformance` -> `Run workflow`.

Select branch:

```text
feat/cognitive-os-v1-5
```

Leave the prefilled values unchanged unless the release owner deliberately chooses a different independent cloud pair:

```text
provider            openai
base_url            https://api.openai.com/v1/chat/completions
api_key_env          CONFORMANCE_API_KEY
sut_model            gpt-5.6-terra

grader_provider     google-gemini
grader_base_url     https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
grader_api_key_env  GRADER_API_KEY
grader_model        gemini-3.7-flash

profile             final
```

Then click `Run workflow`.

## Required result

Stable release requires all of the following from the generated report:

- status `COMPLETE`;
- `release_gate_eligible=true`;
- candidate SHA equals the frozen candidate commit actually tested;
- all critical cases pass;
- overall suite reaches the V1.5 required threshold (>=95%);
- SUT identity is observed and remote;
- grader identity is observed, remote and independent;
- no local/loopback/fallback provider was used;
- artifact `v1.5-conformance` is uploaded.

A failed, incomplete, rate-limited, unobserved-identity or unavailable run is not promotion evidence. Fix the blocker and rerun; do not downgrade the gate.

## After PASS

Do not add feature commits. The only allowed changes after final conformance are release-only metadata/evidence changes that preserve the tested skill package fingerprint under the release contract.

Then:

1. record the conformance artifact in final release evidence;
2. resolve the OpenAI host claim as either `HOST_E2E_VALIDATED` or truthful `PLUGIN_SUBMISSION_READY / HOST_SMOKE_PENDING`;
3. promote all metadata from `1.5.0-dev` to `1.5.0`;
4. run final deterministic/privacy/distribution CI;
5. remove Draft from PR #5;
6. merge to `main`;
7. perform post-merge validation;
8. tag/release `v1.5.0` from the verified `main` SHA.
